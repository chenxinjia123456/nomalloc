# Nomalloc - 架构概览

## 系统架构

Nomalloc 采用多层架构设计，每层职责明确：

```
┌──────────────────────────────────────────┐
│            用户应用层                      │
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│              API 层                        │
│  POSIX API | GC API | Stats API | Debug  │
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│          核心分配层                        │
│  Allocator | Size Class | Thread Dispatcher│
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│          缓存管理层                        │
│  Thread-Local Cache | LIRS Cache Manager  │
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│          内存管理层                        │
│  Arena | Chunk | Buddy | Slab | Region    │
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│          垃圾回收层                        │
│  GC Controller | Mark | Compact | Barrier │
└──────────────────────────────────────────┘
                    ↓
┌──────────────────────────────────────────┐
│        操作系统接口层                       │
│  mmap | NUMA | Huge Pages | Arch Specific │
└──────────────────────────────────────────┘
```

## 核心模块

### 1. Size Class（大小分类）

将内存分配请求分类到不同的 size class：

- **小对象**: 8B - 4KB（30 个 size class）
- **中对象**: 4KB - 1MB（17 个 size class）
- **大对象**: > 1MB（直接分配）

**设计目标：**
- 减少内存碎片
- 提高分配速度
- 空间效率优化

### 2. Thread-Local Cache（线程本地缓存）

每个线程独立的缓存池：

- **无锁设计**: 线程本地操作无需同步
- **自适应容量**: 根据命中率动态调整
- **批量填充/刷新**: 提高吞吐量

**性能目标：**
- 命中率 > 80%
- 延迟 < 100ns

### 3. LIRS Cache（缓存淘汰算法）

双层 LIRS 算法：

- **tcache 层**: HIR 比例 10%，快速淘汰
- **arena 层**: HIR 比例 20%，全局淘汰

**优势：**
- 比 LRU 更高的命中率
- 更好的内存复用
- 抗扫描模式攻击

### 4. Arena（内存区域）

多 Arena 并行管理：

- **NUMA 绑定**: 每个 NUMA 节点独立 Arena
- **Chunk 管理**: 2MB Chunk 单元
- **Buddy + Slab**: 大块 + 小块混合管理

**设计目标：**
- 减少 NUMA 跨节点访问
- 并行分配无竞争

### 5. Garbage Collection（垃圾回收）

G1 风格增量并发 GC：

- **Region 管理**: 用户可配置大小（4KB-256MB）
- **并发标记**: 三色标记 + SATB 写屏障
- **增量整理**: 暂停时间 < 100ms

**触发策略：**
- 自动触发：内存超过水位线
- 手动触发：用户 API 调用

### 6. NUMA 优化

NUMA 感知内存分配：

- **拓扑检测**: 启动时检测 NUMA 结构
- **本地优先**: 线程绑定本地 Arena
- **避免跨节点**: 减少远程内存访问

### 7. 架构优化

x86_64 和 ARM64 特定优化：

- **原子操作**: 架构特定原子指令
- **内存屏障**: 架构特定屏障指令
- **预取指令**: 架构特定预取优化

## 内存分配流程

```
malloc(size)
    ↓
Size Class 映射
    ↓
查询 tcache
    ├─ 命中 → 返回
    ↓ 未命中
查询 arena
    ├─ 有空闲块 → 返回并填充 tcache
    ↓ 无空闲块
从 OS 申请内存（mmap）
    ↓
创建新 Region（GC 管理）
    ↓
返回内存
```

## 性能设计目标

| 指标 | 目标 |
|------|------|
| 吞吐量 | >= jemalloc |
| P99 延迟 | <= jemalloc (< 500ns) |
| GC 暂停 | < 100ms |
| 碎片率 | < 15% |
| 内存利用率 | > 85% |

## 关键设计决策

1. **Size Class 考虑 jemalloc 设计**
   - 细粒度划分减少碎片
   - 对齐到缓存行提高性能

2. **tcache 设计考虑 mimalloc**
   - 线程本地无锁缓存
   - 自适应容量调整

3. **LIRS 算法考虑学术界研究**
   - 比 LRU 更优的缓存淘汰
   - 双层应用提升整体效率

4. **GC 设计考虑 G1**
   - Region 可配置灵活性
   - 增量并发低暂停

5. **NUMA 设计考虑 Linux 内核**
   - 本地内存优先分配
   - 减少跨节点访问

## 模块依赖关系

```
API 层 → 核心分配层 → 缓存管理层 → 内存管理层 → GC 层 → OS 层 → Utils 层
```

每个模块职责明确，接口清晰，便于维护和测试。
